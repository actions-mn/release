A GitHub Action that compiles Metanorma documents and publishes them as **per-document GitHub Releases**.

Part of the https://github.com/actions-mn[`actions-mn` ecosystem] — alongside https://github.com/actions-mn/site-gen[site-gen], https://github.com/actions-mn/compile[compile], and https://github.com/actions-mn/build-and-publish[build-and-publish].

toc::[]

== How it works

. Compiles all documents via `metanorma site generate`
. Discovers compiled documents from their RXL metadata
. Filters by visibility (from `metanorma.release.yml`)
. Detects changes (content hash vs. last release)
. Packages each changed document as a zip
. Publishes as per-document GitHub Releases

Downstream portals discover participating repos via the `metanorma-release` GitHub topic and aggregate released artifacts — no submodules, no compilation needed on the index side.

== Quick start

=== Single document repo

[source,yaml]
----
# .github/workflows/release.yml
name: Release
on:
  push:
    branches: [main]

jobs:
  release:
    runs-on: ubuntu-latest
    container: metanorma/metanorma:latest
    permissions:
      contents: write
    steps:
      - uses: actions/checkout@v4
      - uses: actions-mn/release@v1
        with:
          agree-to-terms: true
          token: ${{ secrets.GITHUB_TOKEN }}
----

=== Multi-document repo with visibility control

Add a `metanorma.release.yml` to control which documents are publicly released:

[source,yaml]
----
# metanorma.release.yml
documents:
  - source: sources/cc-51015.adoc
  - source: sources/cc-51024.adoc
  - source: sources/cc-51026.adoc
    visibility: private  # not ready for public release
----

[source,yaml]
----
# .github/workflows/release.yml
name: Release
on:
  push:
    branches: [main]
    paths: ['sources/**', 'metanorma.yml', 'metanorma.release.yml']

jobs:
  release:
    runs-on: ubuntu-latest
    container: metanorma/metanorma:latest
    permissions:
      contents: write
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0
      - uses: actions-mn/release@v1
        with:
          agree-to-terms: true
          token: ${{ secrets.GITHUB_TOKEN }}
----

=== Explicit release via tag signal

Push a `release/*` tag to trigger a forced release:

[source,yaml]
----
# .github/workflows/release.yml
on:
  push:
    tags: ['release/**']

jobs:
  release:
    runs-on: ubuntu-latest
    container: metanorma/metanorma:latest
    permissions:
      contents: write
    steps:
      - uses: actions/checkout@v4
      - uses: actions-mn/release@v1
        with:
          agree-to-terms: true
          force: true
          token: ${{ secrets.GITHUB_TOKEN }}
----

== Inputs

[cols="1,1,3"]
|===
| Input | Default | Description

| `source-path`
| `.`
| Source path containing the metanorma configuration

| `config-file`
| `metanorma.yml`
| Metanorma configuration file name

| `release-config`
| `metanorma.release.yml`
| Release manifest file (visibility filter)

| `output-dir`
| `_site`
| Output directory for compiled documents

| `agree-to-terms`
| `true`
| Agree to all third-party licensing terms (fonts)

| `install-fonts`
| `true`
| Install missing fonts automatically

| `continue-without-fonts`
| `true`
| Continue processing even when fonts are missing

| `use-bundler`
| `false`
| Use bundler to execute metanorma

| `force`
| `false`
| Force release even if content hash matches last release

| `include-pattern`
| `*`
| Glob pattern to filter documents for release (e.g. `cc-*`)

| `token`
| `${{ github.token }}`
| GitHub token for creating releases
|===

== Outputs

[cols="1,3"]
|===
| Output | Description

| `released-documents`

| `skipped-documents`
| JSON array of skipped document identifiers (unchanged)

| `total-documents`
| Total number of documents processed

| `metanorma-version`

== Release tag convention

Each document gets its own release tag and asset, independent of other documents in the same repo.

[cols="2,1,1,1"]
|===
| Document type | Stage | Tag | Asset

| CC standard
| Published
| `cc-51015/ed1.0`
| `cc-51015-ed1.0.zip`

| CC standard
| Working Draft
| `cc-51015/ed2.0-wd`
| `cc-51015-ed2.0-wd.zip`

| CC standard
| Committee Draft
| `cc-51015/ed2.0-cd`
| `cc-51015-ed2.0-cd.zip`

| ISO
| Published (60.60)
| `iso-8601-1-2019/ed1.0`
| `iso-8601-1-2019-ed1.0.zip`

| ISO
| WD (20.20)
| `iso-wd-8601-1-2026/ed2.0-wd`
| `iso-wd-8601-1-2026-ed2.0-wd.zip`

| IETF I-D
| —
| `id-calext-jscalendar/32`
| `draft-ietf-calext-jscalendar-32.zip`

| IETF RFC
| Published
| `rfc-8984/1`
| `rfc-8984.zip`
|===

[TIP]
====
Published releases are **immutable** — the tag is created once and never overwritten.
Draft releases are **rolling** — the same tag is updated in-place as the draft evolves.
When a document transitions from draft to published, a new tag is created (e.g. `ed2.0-wd` → `ed2.0`).
====

== Release manifest

The `metanorma.release.yml` file controls which documents in a repo are eligible for public release.

If this file is absent, all documents are released (backward compatible).

[source,yaml]
----
# metanorma.release.yml
documents:
  - source: sources/cc-51015.adoc          # visibility: public (default)
  - source: sources/cc-51024.adoc
  - source: sources/cc-51026.adoc
    visibility: private                     # withheld from public release
  - source: sources/draft-ietf-calext-caldav-attachments.adoc
----

Visibility values:

[cols="1,3"]
|===
| Value | Effect

| `public` (default)
| Document is compiled, packaged, and released

| `private`
| Document is compiled but not released publicly

| `members`
| Reserved for future use (member-only access)
|===

== Change detection

The action uses **content hashing** to avoid re-releasing unchanged documents.

. After compilation, SHA-256 hash all files in each document's output directory
. Compare against the hash stored in the previous GitHub Release body
. If the hash matches → skip (unchanged)
. If the hash differs → package and release

The hash is stored in the first line of the release body: `content-hash:{sha256hex}`.

== Discovery via GitHub topics

Add the `metanorma-release` topic to your repository to opt in to portal discovery:

[source,bash]
----
gh api repos/{owner}/{repo}/topics -X PUT \
  --field names='["metanorma-release"]'
----

Portals discover participating repositories:

[source,bash]
----
curl "https://api.github.com/search/repositories?q=topic:metanorma-release+org:CalConnect"
----

== Selective release

In multi-document repositories, only documents that changed since their last release are published:

```
Push to main → compile all → discover 5 documents
  → cc-51015: hash unchanged → SKIP
  → cc-51024: hash unchanged → SKIP
  → cc-51025: hash changed   → RELEASE
  → cc-51026: private        → FILTERED
  → id-calext-jscalendar-32: hash unchanged → SKIP
```

== Architecture

The action follows a pipeline pattern with pluggable interfaces at each stage:

```
metanorma.yml ──┐
                 ├──► Compile ──► Discover ──► Filter ──►
metanorma ───────┘    (site-gen)   (RXL      (release
.release.yml                       scan)     manifest)

───► Detect ──► Package ──► Tag ──► Publish
     (content     (zip)    (tag     (GitHub
      hash)                naming)  Releases)
```

Each stage is defined by an interface (`IDocumentExtractor`, `IVisibilityFilter`, `IChangeDetector`, `IArtifactPackager`, `IReleasePublisher`), making the pipeline extensible without modifying existing code.
